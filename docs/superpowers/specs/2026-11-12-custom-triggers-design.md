# 自定义触发源 / 目标 + Win11 视觉重做 设计

日期：2026-11-12
状态：待确认

## 1. 意图

现在的触发源写死在代码里（麦克风 + `VideoSourceProcesses` 里的 Edge/Chrome/PotPlayer），
目标也只是三条固定记录，用户无法增删。用户希望：

- 自己和程序打交道的软件都能作为触发源或目标，而不是被作者预设的白名单限制
- 界面不再是小字号、无质感的工具面板

同时用户明确担心「配置会变混乱」，所以本设计的首要目标是**把配置压平成两张表**，
而不是引出一张「触发源 × 目标」的矩阵。

## 2. 目标

1. 触发源两类：
   - **麦克风**：沿用现有的采集设备占用判断，保留「忽略的麦克风占用」名单
   - **视频播放**：视频程序列表里任一程序正在输出音频
2. 目标两类，互斥（一个进程只能出现在一个列表里）：
   - **音乐程序**：可被压低，也可被暂停
   - **视频程序**：只可被压低
3. 视频播放触发不压低视频类目标（不存在「自己压自己」）
4. 每个音乐程序单独配置暂停快捷键
5. 添加程序：下拉选择 + 手动输入；下拉支持三种候选范围
6. 界面：Win11 风格，窗口材质可选 Mica / Acrylic / 无，卡片半透明，字号整体放大
7. 旧配置自动迁移，不丢用户设置

## 3. 非目标

- 不做通用规则引擎（不提供「触发源组 × 目标组」的自由映射）
- 不提供 exe 文件选择器
- 不支持视频程序暂停
- 不做自定义主题色编辑器

## 4. 反目标（即使功能可用也算失败）

- 毛玻璃导致文字对比度下降
- 配置界面重新出现矩阵式布局
- 旧版本升级后行为与升级前不一致，或丢失用户数据

## 5. 约束

- `net10.0-windows`，`SupportedOSPlatformVersion` 为 10.0.17763（Win10 1809+ 仍要能跑）
- 不使用绿色（用户既有偏好）
- 浅色模式正文近黑，深色模式正文高对比（用户既有偏好）
- 每次界面改动都升版本号
- 技术栈不变：WPF + NAudio，不引入新依赖

## 6. 配置模型 v3

```jsonc
{
  "Version": 3,
  "Mic":   { "Enabled": true, "ThresholdDb": -45, "SustainMs": 200, "HoldMs": 400 },
  "Video": { "Enabled": true, "ThresholdDb": -50, "SustainMs": 300, "HoldMs": 400 },

  "ScanMsCapture": 200,
  "IgnoredCaptureProcesses": [],

  "MusicTargets": [
    {
      "Id": "kugou",
      "Name": "酷狗音乐",
      "Processes": ["KuGou"],
      "Enabled": true,
      "OnMic": "Pause",          // None | Duck | Pause
      "OnMicDuckTo": 0.2,
      "OnVideo": "Duck",
      "OnVideoDuckTo": 0.2,
      "PauseHotkey": { "Ctrl": true, "Shift": true, "Alt": true, "Key": "F8" },
      "AttackMs": 120,
      "ReleaseMs": 400
    }
  ],

  "VideoTargets": [
    {
      "Id": "...",
      "Name": "Edge",
      "Processes": ["msedge"],
      "Enabled": true,
      "OnMicDuckTo": 0.3,
      "AttackMs": 120,
      "ReleaseMs": 400
    }
  ],

  "WindowMaterial": "Mica",      // None | Mica | Acrylic
  "Window": { ... }
}
```

删除的字段：`VideoSourceProcesses`、`KuGouPauseHotkey`、`Targets`、`TargetSettings.MediaSessionPrefixes`。

**一行 = 一个程序，`Processes` 可挂多个进程名**（同一程序的 32/64 位版本，如 `PotPlayerMini64` 与
`PotPlayerMini`）。进程按名字匹配，同名多 PID 会自动聚合成一条，所以 Chrome 开再多进程也只填一次。

`MediaSessionPrefixes` 移除的原因：名称匹配用于 MediaSession 暂停，改为按 `Process` 反查媒体会话即可，
现有前缀表本身也是从进程名派生的。

## 7. 行为矩阵

| 触发 | 音乐程序 | 视频程序 |
| --- | --- | --- |
| 麦克风占用 | 每程序：压低 / 暂停 / 不处理 | 压低 |
| 视频程序出声 | 每程序：压低 / 暂停 / 不处理 | 不处理 |

## 8. 界面

### 8.1 页头

```
AutoVolume  音量自动闪避  v1.5.0        [运行中]   [深色模式]  [材质：Mica ▾]
```

- 「材质」下拉：无 / Mica / Acrylic，紧挨现有的主题切换按钮
- 系统不支持（Win10、关闭了透明效果）时自动按「无」渲染，下拉仍可操作但显示灰色说明

### 8.2 触发源

保持现有两行（麦克风、视频播放）及参数，另加一个「麦克风扫描」输入框（对应 `ScanMsCapture`，默认 200 ms）。

采集会话扫描与输出会话扫描拆开：

| 扫描 | 周期 | 理由 |
| --- | --- | --- |
| 采集会话（麦克风占用） | `ScanMsCapture`，默认 200 ms | 二值信号，延迟直接可感 |
| 输出会话（视频电平） | 固定 1000 ms | 枚举开销大，视频信号本身容忍 1 秒 |

### 8.3 目标 —— 两张表

每张表结构相同：节标题 + 过滤三段 + 添加行 + 条目行。

```
音乐程序 ──────────────────────────────── [应用进程|全部进程|仅正在出声]
┌─────────────────────────────────────────────────────────────────────┐
│ [ 选择程序 ▾ ] [ 添加 ]  或手动输入 [ ____________ ] [ 添加 ]        │
│ ─────────────────────────────────────────────────────────────────── │
│ 酷狗音乐  麦克风[暂停▾][—]  视频[压低▾][20%]  [热键输入框]      [×] │
└─────────────────────────────────────────────────────────────────────┘

视频程序 ──────────────────────────────── [应用进程|全部进程|仅正在出声]
┌─────────────────────────────────────────────────────────────────────┐
│ [ 选择程序 ▾ ] [ 添加 ]  或手动输入 [ ____________ ] [ 添加 ]        │
│ ─────────────────────────────────────────────────────────────────── │
│ Edge      麦克风[30%]                                           [×] │
└─────────────────────────────────────────────────────────────────────┘
```

- 过滤三段互斥，**不写入配置**，只影响当前下拉候选
  - 应用进程（默认）：运行中的进程，滤掉系统进程
  - 全部进程：不过滤
  - 仅正在出声：当前有音频输出的进程
- 一行可挂多个进程名（如 `PotPlayerMini64`、`PotPlayerMini`），程序名格把它们并列显示；
  需要追加时点该格的「+」，把下拉或手输的进程名并入这一行
- 每个目标行还带一个「渐变」输入框（`AttackMs`，默认 120 ms），控制压低 / 恢复速度
- 程序已在另一个列表中时，拒绝添加并提示
- 音乐程序之间快捷键冲突时提示，仍允许保存
- 列表为空时显示占位说明（「视频程序为空时，视频播放不会触发任何压低」）

### 8.4 视觉

- 窗口材质：`DwmSetWindowAttribute(hwnd, DWMWA_SYSTEMBACKDROP_TYPE /*38*/, value)`，
  2 = Mica，3 = Acrylic，1 = 无
- 卡片：浅色 `#B3FFFFFF` / 深色 `#99000000`，8px 圆角，1px 细边框
- 字号整体 ×1.15：

| 用途 | 现在 | 目标 |
| --- | --- | --- |
| 正文 / 控件 | 12 ~ 12.5 | 14 |
| 行标题 | 13 ~ 13.5 | 15 |
| 节标签 | 12.5 | 13.5 |
| 窗口标题 | 19 | 21 |
| 底部说明 | 11.5 | 12.5 |

- 文字永远落在实底卡片上，不直接压在半透明背景上

## 9. 迁移（v2 → v3）

按旧 `Targets` 的 `Id` 分类：

| 旧目标 | 新归属 | 映射 |
| --- | --- | --- |
| `kugou` | 音乐 | 整条迁移，`PauseHotkey` 取旧 `KuGouPauseHotkey` |
| `potplayer` | 视频 | 整条迁移，`Processes` 原样保留（仍是同一行） |
| `browser` | 视频 | 整条迁移，`Processes` 原样保留（仍是同一行） |
| 其它未知目标 | 视频 | 一律归视频（只压低、不暂停，行为更保守） |

`Version` 置 3，`Normalize()` 负责补齐缺失字段与夹取范围。

## 10. 实施步骤

分两步，各自可独立验收、独立升版本。

**第一步：功能（1.4.0）**
1. `Config.cs`：v3 模型 + 迁移 + 校验
2. `AudioEngine.cs`：视频触发源改为读 `VideoTargets`；取消视频触发对视频目标的压低；音乐程序按各自 `PauseHotkey` 发送暂停
3. `MainWindow.xaml(.cs)`：两张表 + 添加流程 + 三段过滤
4. README / 版本号

**第二步：视觉（1.5.0）**
1. DWM 材质 + 回退
2. 卡片半透明与圆角
3. 字号放大
4. 浅色 / 深色截图核对

## 11. 实现者可以自行决定的部分

- 系统进程过滤名单的具体内容（可复用 `/src/Config.cs` 的 `SystemIgnoredProcesses` 并扩充）
- 友好显示名的映射表（已知进程给中文名，未知进程直接显示进程名）
- 音乐程序未配置热键时，暂停回退到 MediaSession
- 下拉候选的排序方式（建议：正在运行的在前，按名称排序）
- 切换材质是否需要重建窗口（优先尝试运行时直接设置）
